# 火災黃金30秒 — THE GOLDEN 30 SECONDS

Three.js 展場網頁。兩頁：**火災黃金30秒**（倒數）與**首頁**（逃生動線示範）。

## 開機流程

**歡迎頁一律是「火災黃金30秒」** —— 不管是重新整理還是別人拿網址進來，第一眼看到的都是它。
`?page=` 仍然可以指定開在哪一頁（截圖／測試用），但**只在開這一次有效**：
套用完 `main.js` 就用 `history.replaceState` 把它從網址上拿掉，重新整理就回到黃金30秒，
不會有人不小心把 `?page=home` 的網址傳出去、讓展場機器卡在首頁當歡迎頁。

停在歡迎頁之後，**倒數跑完一輪（30 秒）自動進首頁**。

- 只會自動跳這一次。手動切過頁之後就不再干涉，按 `Esc` 回黃金30秒不會又被跳走。
- 正在編輯版面（`E`）時不會跳，離開編輯模式後的下一輪才會。
- 要改流程改 `js/main.js` 最上面的 `WELCOME_FROM` / `WELCOME_TO`；不想自動跳就把
  `createCountdown` 的 `onEnd` 拿掉。

## 首頁（ENTER）

標題「雲端宅邸」、左側 3D 區、**右上標語 + 即時狀態面板**、右側**逃生動線示範**的兩顆按鈕、
左下三個功能鍵（立即警報 / 逃生路線 / 安全法規）、右下大樓標語。

### 右上：標語 + 即時狀態面板

「即時感知 × 動態判斷 × 智慧分流」加上四列狀態。

待機（藍）時有兩個動態效果，都由 `js/main.js` 的 `startIdleFx()` / `stopIdleFx()` 一起開關，
**跑動線（紅）和通關（綠）時都會停掉**：

1. **「展示逃生動線」按鈕跟著時間軸抽** —— **兩種風格混在一起**：
   **A（訊號壞掉）**真的疊一層雜訊（橫掃描線 + 顆粒 + 撕裂遮罩，一格一格硬跳，整體忽亮忽暗）、
   **B（橫向殘影）**框線／圖示／文字往右糊出去再收回來，圖示和文字還會真的位移。
   A 給「壞掉」的髒感，B 給「訊號被拉走」的動感，**兩個同時發生**才像映像管真的在抽，
   跟綠色樓梯同一套語言。**不是固定週期的循環，而是每次擺盪走到時間軸的一個點就抽一次**
   （`viewer.onSwingBeat` → `js/main.js` 的 `glitchPlayBtn()` → `glitchBtn()` 掛上 `.is-glitch`
   跑一次 0.5 秒的 one-shot 動畫，`animationend` 再自己拿掉）。
   一次的節奏：**衝出去 → 收 → 再衝一次（比較大）→ 收 → 小抖一下 → 乾淨**。
   ⚠️ 重播同一個動畫要**先移除 class、強制重排（`void el.offsetWidth`）再加回去**，
   直接再 `add` 同一個 class 是不會重播的。
   ⚠️ **剛進待機的第一拍不抽**（`skipGlitch`）—— 一進場就閃太吵，第二拍才開始。
   標語不受影響，進場那一拍照樣亮起第一個詞。
   ⚠️ 另外還有一道 `PAGE_FADE`（420ms）的延後：`.page` 的淡入是 .42s，
   如果某一拍剛好落在切頁的淡入期間，抽動會整段跑在看不見的時候。
   延後只做一次（`force`），不要寫成「等到看得見為止」的迴圈：預覽窗格不合成、或
   `prefers-reduced-motion` 的情況下 `opacity` 可能永遠讀不到 1，會變成無限重試。

   五層一起動：

   | 層 | 動畫 | 做什麼 |
   | --- | --- | --- |
   | `.home__route-noise` | `routeNoise` + `routeScan` + `routeTear` | **A**：雜訊忽隱忽現、掃描線跳捲、撕裂區塊左右跳 |
   | `::after` | `routeBlink` | **B** 框線殘影 + **A** 的整體提亮（`brightness`） |
   | `::before` | `routeBlinkFill` | 底光閃一下 |
   | `.home__route-ico svg` | `routeBlinkIco` | 圖示殘影 + 位移 + 提亮 |
   | `.home__route-label` | `routeBlinkTxt` | 文字殘影 + 位移 |

   **不會比原本更暗**（0%／100% 那兩格就是按鈕原本的樣子）。

   ⚠️ **快回到點 1 的那幾秒，頻率改成跟樓梯一樣**：綠樓梯在回程末段（q ≥ 0.78）會連抖，
   每抖一下 viewer 就發一次 `onStairBlink`（2 次主抖 + 各自的收尾小抖，共 4 下，
   落在 q = 0.78 / 0.871 / 0.89 / 0.981），`js/main.js` 收到就讓按鈕抽一次。
   所以那一段按鈕和樓梯是完全同步的，中間那兩下只差 0.35 秒，會像訊號連續斷兩下。
   這一條走 `glitchBtn()` 而不是 `glitchPlayBtn()`：不吃 `skipGlitch`、也不用等頁面淡入。

   **位移**：框線只有殘影（不真的移動），圖示和文字是真的 `translateX` ——
   圖示最大 +4px、文字最大 +6px，**右邊推得比左邊遠**（左邊只回彈 1～2px），
   跟殘影的方向一致。要調就改 `routeBlinkIco` / `routeBlinkTxt` 的 `translateX`。

   **雜訊是獨立的一層**（`<span class="home__route-noise">`，兩顆按鈕各一個），不是背景圖：
   `position:absolute; inset:0; z-index:2`（蓋在文字和框線上面）、`mix-blend-mode:screen`
   （只會提亮不會壓暗）、`clip-path:var(--shape)`（裁成倒角，不會溢出按鈕外面）。
   背景疊三層：兩組週期不一樣的橫條紋（**11px / 29px**，互相打拍就會很亂）+ 一層
   `feTurbulence` 的細顆粒（內嵌 SVG data URI）。平常 `opacity:0`，抽動時才被 `routeNoise` 打開。

   ⚠️ **一定要有那層撕裂遮罩**（`mask-image`）：沒有它整條按鈕會一起亮，看起來很均勻、
   不像壞掉的訊號。遮罩是寬 **240%** 的不規則橫向區塊，`routeTear` 讓它每一格跳到不同位置，
   所以每一瞬間只有幾塊在閃、其他地方是乾淨的。
   ⚠️ 掃描線的抖動放在 `background-position`，**不要放 `transform`** —— `transform` 會把
   裁好的倒角一起移出去，邊緣會露餡。
   ⚠️ `routeNoise` 的節奏（0/12/20/28 … 68/76/84/92）跟殘影的（0/16/34/56/76/90）
   **故意不對齊** —— 對齊了就變成「一起呼吸」，錯開才像兩件事同時壞掉。
   要更髒／更乾淨改 `routeNoise` 的 opacity 值，或 `.home__route-noise` 裡三層背景的濃度。

   **顏色不用切**：所有 keyframes 吃的是 `--gl`（= `--brand-hi`）和 `--gl-soft`（= `--brand`），
   而 `:root[data-theme="green"]` 本來就把 `--brand-hi` 換成綠的，
   所以同一組動畫「藍的時候藍、綠的時候綠」，不需要另外寫一個綠色版本。

   ⚠️ 殘影是用 **`drop-shadow` 串**做的，不是額外疊一層元素：`drop-shadow` 吃的是元素的
   **alpha 形狀**，而框線畫在 `.chamfer` 的 `::after`（`clip-path` 切出來的中空八邊形）上，
   所以影子會完全照著倒角的形狀跑，不是一個矩形。串在一起的每一層都是「上一層結果」的影子，
   會疊成一條拖尾。
   ⚠️ 每一格的 `filter` **函式數量要一模一樣**，不然不會平滑內插、會變成硬跳；
   乾淨的那幾格用 `drop-shadow(0 0 0 transparent)` 補位。
   ⚠️ **右邊的殘影推得比左邊遠、也比左邊濃**（例如最大那一格是 `+8 / -4 / +15 / -8` px）——
   這就是「右邊更亮、左邊更暗」。
   ⚠️ `--stroke` / `--bw` 那種自訂屬性**沒辦法內插**，不要想用它們做動畫。

   要調就改 `@keyframes routeBlink` / `routeBlinkIco` 的偏移量（糊多開）和 `%`（節奏），
   那三條 `.5s` 是總長度；已加 `prefers-reduced-motion` 的關閉規則。
2. 右上標語三個詞依序亮起（見下）。

**通關（綠）之後換「切換逃生動線」抽**，同一套動畫、綠色（見上面「顏色不用切」）。
綠色介面的鏡頭是在自轉、沒有 `onSwingBeat` 可以掛，所以 `startGreenFx()` 自己走計時器，

**進場那一拍不抽**（先等一拍再開始），跟藍色的 `skipGlitch` 一致。
`stopGreenFx()` 掛在「又按了按鈕」和 `resetRouteDemo()`（離開首頁／回藍色）兩個地方。
⚠️ 編輯模式用側欄切到「通關」不會啟動它（那邊只換配色和版面，不跑效果）。

**只有待機會跑** —— 按下按鈕跑動線（紅）和通關（綠）時整條標語都是原本的顏色，不輪替。

`.home__tagline b:nth-of-type(n).is-on` 三條。

列與列之間一條細分隔線（`--brand-line`）。每一列是「圖示 + 名稱 + 右側小字」。

⚠️ **巢狀的編輯物件**（`homeSub` 在 `homeTagline` 裡、第一頁的 `sideTag` 在 `sideHead` 裡）：
子物件的 x/y/w/h 是**相對外框、而且會吃外框的 scale**，所以子物件自己的 `s` 維持 1、

### 逃生動線示範（右側兩顆按鈕）

原本的歡迎／登入面板已經拿掉，換成 **展示逃生動線** 和 **切換逃生動線**。
兩顆按鈕跑的流程一樣，**差別只在挑哪一條**：

| 按鈕 | 挑哪一條 |
| --- | --- |
| **展示逃生動線** | **重複「目前這一條」** —— 待機時是正在冒煙的那一條，通關之後是剛剛跑過的那一條 |
| **切換逃生動線** | **隨機挑別條**，避開「目前這一條」 |

所以通關之後想再看一次同一條就按「展示」，想換一條就按「切換」。
（動線只有一條時，「切換」也只能重播那一條。）

流程本身兩顆都一樣：

1. 整個介面切成**紅色主題**（`?theme=red` 那一組）
2. 隨機挑一條逃生動線，**依它的長度換算秒數**（固定行走速度）從紅色起點沿折線畫到綠色出口
   線是**綠色**的，線頭有一個**白色的逃生小人**跟著跑）；
   **這條動線有設過機位的話，鏡頭會用 0.8 秒平順飛過去並停在那裡**
3. 抵達出口 → **小人站在綠色出口上停 0.5 秒**（動線還畫著）→ **3D 黑掉**（版面上的字和按鈕留著）
   → 介面切成綠色主題、路線收掉、整棟建物變成白色實心、鏡頭直接就定位 → 亮起來，跳出「**恭喜通關**」

**狀態切換一律用黑幕，不用鏡頭飛過去銜接**（黑 0.22 秒 → 換好 → 亮起來）。
飛過去的話鏡頭會從動線的角度硬轉到通關的角度，很怪；黑掉直接就定位乾淨得多。

**只黑 3D 那一塊**，標題、按鈕、標語、恭喜通關都不會跟著消失 ——
黑幕（`index.html` 的 `.blackout`）是放在 `.home__stage` 裡面的，`z-index:2` 疊在 canvas 上、
在舞台標籤（`z-index:3`）下面。時間在 `js/main.js` 的 `FADE_OUT`，要和 CSS 的 transition 一致。

#### 動線那條線的長相（只有首頁）

首頁的動線是**粗的紅色發光虛線**；**第一頁（黃金30秒）維持原本的細綠虛線，沒有動到**。

線是**照進度一段一段長出來**的。想要一開始就畫滿整條路的話，
`js/main.js` 的 `viewer.playRoute()` 加一個 `whole: true`。

⚠️ **粗線的段數從頭到尾固定不變**，還沒跑到的段是「收合到線頭上」（長度 0 所以看不見），
不是真的把段數改少。原因見下面那段警告。

WebGL 的 `THREE.Line` 畫不出寬度（`linewidth` 幾乎都被鎖在 1px），所以首頁改用 addons 的 `Line2`：
一條「核心」加一條更寬的「光暈」（相加混色）疊出發光感，兩條**共用同一份 geometry**，畫到哪裡只更新一次。

| 想調 | 改哪裡（`js/viewer.js` 最上面的 `ROUTE_LINE`） |
| --- | --- |
| 線多粗 | `width`（目前 `3.4`，單位是**螢幕像素**，拉遠拉近都一樣粗） |
| 線頭小人多大 | `js/viewer.js` 的 `RUNNER.size`（`1.0` 個模型單位，一層樓約 3.5） |
| 小人的光暈 | `RUNNER.glow`（`2.2` = 光暈是本體的 2.2 倍大）／`RUNNER.glowOp`（`0.55` 濃度）；`RUNNER.light` 是他隨身那顆白光 |
| 線頭小人長什麼樣 | `runnerTexture()` 裡那幾行 `line([...])` 的座標（0~1 的比例，改了就換姿勢） |
| 光暈多寬／多濃 | `halo`（`12` 像素）／`haloOpacity`（`0.2`） |
| 虛線多密 | `dash` `0.32` ／ `gap` `0.2`（模型單位，**數字越小越密**；第一頁那組是 0.7 / 0.45） |
| 線的顏色 | 兩頁都吃 `--exit`（安全出口的綠，語意色不隨主題變） |

⚠️ `Line2` 的像素寬度要靠 `material.resolution`，**換視窗大小一定要重設**，
所以 `viewer.resize()` 會呼叫 `_syncLineRes()`。加新的粗線材質記得 push 進 `this._lineMats`。

⚠️ **不要用 `setPositions()` 改段數。** three 只在「第一次繪製這份 geometry」時決定
`_maxInstanceCount`，之後段數變多也不會跟著長 —— 按下按鈕時線只有 1 段，就會被鎖在 1，
整條動線永遠只畫得出第一段。所以 `_drawRouteAt()` 是**改座標不改段數**。

**動線上的點照路徑長度等速跑**：秒數 = 路徑長度 ÷ `ROUTE_SPEED`，所以每條的點速度都一樣
（`6.4 / 1.5` ≈ 4.27 單位/秒），不會忽快忽慢。目前五條約 **8.5 ~ 10.7 秒**。
編輯模式的時間軸會顯示該條自己的總秒數。

**鏡頭不跟著點跑**：它會在**每個關鍵影格停 `CAM_HOLD` 秒（預設 0.25）**，然後滑到下一個影格，
到了再停。所以鏡頭是「停 → 轉 → 停 → 轉 → 停」，不是一路連續掃過去。
剩下的時間按「這一段鏡頭要走多遠」分給各段，每一段自己加減速。
**鏡頭和點不會完全對齊**，這是刻意的取捨（要對齊就得讓點忽快忽慢）。

「整棟變白」是把半透明玻璃牆板換成白色樓板那組材質（`--m-slab`、不透明），
並套一層**由上往下的陰影漸層**：上面是 `--m-slab`、下面壓到 `--m-shade`，
自發光也從平常的 .35 降到 .07 —— 不然整棟自己在發光，會亮得很均勻、看不出立體感。
離開通關狀態就換回玻璃。

| 想調 | 改哪裡 |
| --- | --- |
| 陰影是什麼顏色 | `css/style.css` 各主題的 `--m-shade`（藍 `#4d6a86` / 綠 `#3f7d63` / 紅 `#8a544c`） |
| 陰影吃掉多少高度 | `js/viewer.js` 最上面的 `SHADE.span`（`0.55` = 下面 55% 是漸層，上面維持白） |
| 整體要更深 / 更亮 | `SHADE.emissive`（`0.07`；**越大底部越亮、層次越平**，設 0 就完全靠打光） |

漸層是**頂點色**做的（依世界座標的高度算），算好會快取在 geometry 上，只有換主題才重算。
所以 `--m-slab` / `--m-shade` 改了會自動跟著變，不用重跑模型前處理。

### 待機時的起火點（紅色閃點 + 紅色煙霧）

待機（藍）時會挑一條動線的起點當起火位置，在那裡放一顆閃爍的紅點，並冒出紅色煙霧。
**不會畫路徑** —— 路徑要按了按鈕才出現。

### 待機的時間軸（整組節奏都掛在鏡頭的來回擺盪上）

把一趟擺盪切成四段，鏡頭每經過時間軸上的一個點就發一次 `viewer.onSwingBeat`：

**點 1 和點 4 是擺幅的兩端，點 2 和點 3 把中間平分成三段** —— 也就是擺盪位置
`k = (1-cos θ)/2` 的 0 / ⅓ / ⅔ / 1。換算成相位 θ 是 0 / acos(⅓) / acos(-⅓) / π，
**時間上不是等距的**（餘弦在兩端會變慢）。回程還會再經過點 3、點 2，
所以一個循環總共踩到 **6 拍**（`SWING_BEATS`）：

| 拍 | 點 | k | 方向 | 起火點 | 樓梯 | 標語 | 按鈕 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | **1** | 0 | 正 | **動線 1 或 2** | 白 | 紅字 | 抽 |
| 2 | **2** | ⅓ | 正 | **動線 3** | 白 | 黃字 | 抽 |
| 3 | **3** | ⅔ | 正 | **動線 4 或 5** | 白 | 綠字 | 抽 |
| 4 | **4** | 1 | 端點，轉向 | **維持點 3 那顆，開始淡出** | **轉綠**＋閃一下 | 綠字 | 抽 |
| 5 | **3** | ⅔ | 反 | 維持、繼續淡 | 綠＋**閃一下** | 綠字 | 抽 |
| 6 | **2** | ⅓ | 反 | 維持、繼續淡 | 綠＋**閃一下** | 綠字 | 抽 |

回到點 1 ＝樓梯變回白、起火點重新出現、紅字亮起，一個循環。
**進場的那一次按鈕不抽**（標語照樣亮）。
各段的長度不一樣（目前約 7.4 / 4.1 / 7.4 / 7.4 / 4.1 / 7.4 秒），標語漸強的時間會跟著那一段走。

**每個點綁定哪幾條動線是寫死的**（`SWING_BEATS` 的 `pick`，0 起算所以「動線1」= 0）：
點 1 → `[0, 1]`、點 2 → `[2]`、點 3 → `[3, 4]`。有兩條可選時隨機挑一條並避開剛剛那條；
只有一條時（點 2）就固定用那條。要換綁定改 `SWING_BEATS` 那三行就好。

**整個回程（點 4 → 點 1）起火點會線性淡掉**（紅點、光暈、點光源、煙霧一起），到點 1 剛好歸零，
**點 1 再冒出自己那一顆新的**。
⚠️ 淡掉的那一顆在點 1 是**立刻收掉**、不走 `overlap` 的陪跑 ——
陪跑的話新的一拍會把淡出係數重設成 1，它會整顆「復活」0.25 秒才消失（`_spawnIdleFire` 的 `keepPrev`）。

**綠色樓梯在整個回程都是綠的**，而且會發光、碰到點閃一下、消失前抖兩下
（`js/viewer.js` 的 `STAIR_GREEN`，吃的是「回程走到幾成」`q` 而不是秒數）：

| | 什麼時候 | 做什麼 |
| --- | --- | --- |
| 發光 | q 0 → `swell`（8%） | 自發光推到 `glow`（**1.0**） |
| 碰到點抖一下 | q = 0 / 0.392 / 0.608（點 4 / 3 / 2） | `blip`（6%）長度的一次外溢 |
| 消失前抖兩下 | q ≥ `blinkAt`（78%） | `blinks`（**2**）次，每次一個主要的 + 收尾再抖一小下 |

**「抖」不是整座消失，是橫向外溢再收縮**（映像管訊號糊掉的感覺）：
樓梯左右各疊 `ghosts`（3）層**殘影**（`_makeStairGhosts`，共用同一份 geometry、
不吃光的相加混色材質），抖動時往外推到 `spread`（**0.18** 模型單位）再收回來，
本體同時淡掉 `dim`（50%）—— 看起來像訊號散開，不是多了幾個影子。
一次抖動的曲線是「32% 衝出去、68% 收回來」。

⚠️ **外溢的方向取「相機的右方」**（`_setStairSmear` 用 `camera.matrixWorld` 的第 0 欄，
再 `transformDirection` 換到樓梯父層的區域座標）—— 所以不管鏡頭擺到哪，
外溢永遠是**畫面上的水平方向**，不是模型的某個固定軸。

⚠️ **綠色期間 diffuse 被壓成純黑**，畫面上完全只剩自發光 —— 不然打光會疊在綠色上面，
看起來白白髒髒的（原本樓板的白透出來）。
⚠️ **「熄」是整座樓梯（連框線）藏起來**，不是換回白色 —— 換回白色就會看到原本那座樓梯。

`glow` 為什麼是 1.0：渲染器開著 ACES tone mapping（exposure 1.15），所以材質數值和螢幕顏色不是一比一。
實際量過（渲染到 render target 讀像素）—— **1.0 出來剛好是 `rgb(61,255,161)`**，
跟 `--exit`（`rgb(61,255,160)`）一致，也就是「智慧分流」那個綠。
再往上推只會洗白：1.6 → `rgb(77,255,198)`、2.2 → `rgb(90,255,228)`。

閃的時候是**硬跳**，跟按鈕的雜訊抽動同一個路數 —— 柔和地淡進淡出就變成呼吸燈，
不是壞掉的訊號了。每一次閃的「亮」佔比（`duty`）故意不一樣，才不像節拍器。

一趟 = 2π ÷ (0.9 × |擺盪速度|) 秒（目前約 37.5 秒、一段約 9.4 秒），所以在編輯模式改擺盪速度，
**起火點、樓板變色、標語換字、按鈕抽動四件事的節奏會一起跟著變**。相位對齊 `swing.t0`。
**進場的那一次按鈕不抽**（標語照樣亮）。沒在擺盪才退回 `IDLE_FIRE.every` 的固定秒數（那時只有起火點會換）。

**只有樓梯會變綠**，樓板不動。為了做到這件事，`tools/restyle-tower.mjs` 多輸出了一個
`stair` 材質，`models/tower.glb` 也重新前處理過。
執行期 `_makeBlueprintMats()` 的 `stair` 是 `slab.clone()` —— 平常長得一模一樣，
只有點 4 那一段才把它染成 `--exit`。

**樓梯是怎麼認出來的**：使用者另外從 Revit 匯出一份「只有樓梯」的
`C:\Users\USER\Desktop\vb\3層\梯\樓梯.gltf`，腳本拿它每個 mesh 的
**POSITION min/max 當指紋**去比對主檔（同一份幾何匯出兩次，包圍盒會一模一樣）—— 46 個全中。
⚠️ **不要用節點名判斷**：主檔裡名字含「樓梯」的只有 7 個，而且其中 4 個根本不是樓梯，
反而漏掉底層那一段（之前就是這樣認錯的）。

⚠️ 之後再重跑前處理，記得腳本現在是輸出 **4 個材質**（wall / slab / stair / wall-cut），
每個都要**不同顏色**，不然 `gltf-transform` 的 dedup 會把它們併成一個。

**一顆的壽命就是一拍**（下一拍換位置時它才熄掉），所以中間不會有空白。
下一顆是在舊的熄掉前 `IDLE_FIRE.overlap`（0.25 秒）就先冒出來的，那一小段是**兩處同時在燒** —— 所以每 4 秒換一個位置，
交接的那 0.25 秒**兩處同時在燒**（不是空白，是重疊）。
**沒有淡入淡出**，就是直接開／關；紅點、光暈、點光源、煙霧一起出現／一起消失。

因為要並存，起火點做成**兩格輪流用**（`fire.slots`），不是一顆搬來搬去。
每一格亮起來時煙霧的循環會**重新起算**（`slot.t0`），所以每一次燒起來的樣子都一樣（第一顆從底下冒）。
九顆本來就是錯開相位的，所以還是會有幾顆已經在半空中 —— 這是原本就有的設計。

位置是**從離鏡頭最近的 3 條動線起點裡隨機選一條**，而且**會避開目前這一條**，所以每一輪都真的會換地方。
模型在擺動／自轉的時候，「最近的三條」會跟著轉，起火點也就一直在面前那一帶跳。
（早期版本是「永遠取最近的那一條、每 0.2 秒重挑、要近一成以上才換」，鏡頭不動時起火點就永遠釘在同一個地方。）

**交接的那 0.25 秒有兩處在燒**，這時按下按鈕跑的是**新的那一條**（`idleFireRoute()` 回的是最新的那一顆）。

| 想調 | 改哪裡（`js/viewer.js` 最上面的 `IDLE_FIRE`） |
| --- | --- |
| 每一顆亮幾秒 | `on`（目前 `5` 秒） |
| 前後重疊幾秒 | `overlap`（目前 `0.25` 秒；設 `0` 就是無縫接替，永遠只有一顆。換位置的週期 = `on - overlap`） |
| 從最近的幾條裡挑 | `pool`（目前 `3`；設 `1` 就回到「永遠是最近的那一條」） |
| 要不要避開目前這一條 | `_pickFireStart()` 裡的 `pool.filter`（拿掉就是純隨機，可能連續抽到同一條） |

- 按下按鈕就跑**正在冒煙的那一條**（看到哪裡起火就從哪裡逃）。之後再按才是隨機換別條。
- 煙霧是**卡通風**的：9 顆雲朵狀的 sprite，一顆一顆「啵」地彈出來，邊飄邊轉（一輪 2.6 秒）。
  形狀是**下小上大**（大小 0.8 → 4.0）、顏色**下紅上透**（濃度 0.78 → 0.10），像一柱往上散開的煙。
  貼圖是 canvas 畫的**雲朵剪影**（六個圓的聯集），邊緣是硬的、分成「深外圈 + 亮內裡」兩層，賽璐珞感。
  顏色吃 `--red`（語意色，不隨主題變）。
  
  | 想調 | 改哪裡（`js/viewer.js`） |
  | --- | --- |
  | 幾顆、多大、飄多高多散、幾秒一輪 | `_makeSmoke()` 的 `count` / `size` / `rise` / `spread` / `life` / `opacity` |
  | 雲朵長什麼樣、外圈多深 | `smokeTexture()` 的 `puffs` 座標和 `fill(1.00, 0.5)` / `fill(0.86, 1.0)` 兩層 |
  | 彈出來的力道 | `_updateSmoke()` 裡 `age < 0.18` 那段回彈曲線 |
- 編輯模式選「待機（藍）」也會顯示，選動線或通關就收掉 —— 看到的跟實際跑起來一樣。

### 七個狀態的運鏡各自獨立

**待機（藍）／動線1～5（紅）／通關（綠）** 共七個狀態，每一個都能單獨設定「鏡頭」和「運鏡」，互不影響。
動線是**五條隨機抽**（避開剛剛那一條），不顯示關卡編號。

每個狀態可以存兩樣東西，組合出四種行為：

| 這個狀態存了什麼 | 跑起來的樣子 |
| --- | --- |
| **兩個以上鏡頭點**（時間軸） | 鏡頭沿著行徑進度走（見下面的時間軸） |
| **一個鏡頭點** | 飛過去停在那裡不動 |
| **一個鏡頭點 + 運鏡** | 飛過去，然後照那個運鏡（例如自己轉、來回擺） |
| **只有運鏡、沒有鏡頭點** | 鏡頭留在原地，直接套那個運鏡 |
| **什麼都沒設** | 回到待機的視角和運鏡（藍色那組） |

「運鏡」＝自動旋轉／來回擺動／速度／擺幅／A B 這一整組。程式裡七個狀態共用 `viewer.enterState()` 判斷。

#### 怎麼設

編輯模式（`E`）→ 工具列的「**狀態**」下拉選要編的那一個。**切過去畫面就會整個變成那個狀態的樣子**
（配色、建物外觀、鏡頭、運鏡都會跟著換），所以你看到什麼就是跑起來的樣子：

| 選到 | 畫面會變成 |
| --- | --- |
| 待機（藍） | 藍色主題 + 玻璃牆 + 存好的待機視角與擺動 |
| 動線1~5 | **紅色主題** + 該條動線的時間軸與運鏡 |
| 通關（綠） | **綠色主題 + 整棟變白** + 通關的機位與自動旋轉 |

調好之後按「**設定**」存起來（待機存視角、動線存運鏡、通關存鏡頭+運鏡）。
離開編輯模式會自動切回待機的配色。

通關（綠）沒設過的話，預設是原地慢慢轉（`js/main.js` 的 `GREEN_MOTION`）。

通關之後再按「展示」＝重跑同一條，按「切換」＝換一條（避開剛剛那一條）。
**離開首頁**（`Esc` / `0` / `1`）會收掉動線、
關掉通關訊息、主色回到使用者原本選的那一個（預設藍）。通關訊息在按下一次按鈕或離開首頁之前會一直留著。

| 想改 | 改哪裡 |
| --- | --- |
| 點走多快 | `js/main.js` 的 `ROUTE_SPEED`（目前 `6.4 / 1.5`；**數字越小走越慢**，秒數會跟著變長） |
| 鏡頭在每個影格停多久 | `CAM_HOLD`（目前 `0.25` 秒；設 `0` 就一路滑過去不停） |
| 秒數上下限 | `ROUTE_SECONDS`（目前 `[3, 12]`，避免極端長度的動線跑到天荒地老） |
| 紅／綠是哪兩組色 | `js/main.js` 的 `setTheme('red')` / `setTheme('green')`，色值在 `css/style.css` 的 `:root[data-theme=...]` |
| 動線本身 | `models/routes-home.json`（5 條，由 `tools/extract-home.mjs` 從 BIM 的逃生動線圖抽出，細節見 `HANDOFF.md` 0.4） |
| 通關訊息 | `index.html` 的 `.home__clear`，樣式在 `css/style.css` 的 `.home__clear*` |
| 狀態切換的黑幕 | `js/main.js` 的 `FADE_OUT`（`220`，要和 `css/style.css` 的 `.blackout` transition 一致） |
| 到出口停多久才跳通關 | `js/main.js` 的 `EXIT_HOLD`（`500` 毫秒，設 `0` 就是到了立刻跳） |
| 通關時整棟變白的樣子 | `js/viewer.js` 的 `_applyWallLook()` |

底層是 `viewer.playRoute('tower', {duration, avoidCurrent, onDone})`、`viewer.stopRoute('tower')`、
`viewer.playShot(name, 秒)` / `viewer.releaseShot(秒)`、`viewer.setAllWhite(true|false)`。
首頁那一組動線是 **manual 模式**（平常全部藏著、只有按按鈕才播）；第一頁仍是 auto 模式（每 2 秒自己換一條）。

#### 第一頁的動線輪播和倒數時段對齊

每 `ROUTE_SLOT`（**2 秒**）換一條，倒數一個時段 10 秒，所以一段最多剛好放得下 5 條。
兩件事讓它不會出現「一條只閃過去」：

1. **格子對齊時段的起點**。`setRoutePhase(idx, seconds)` 會把起訖記在 viewer 上
   （`_phaseT0` / `_phaseEnd`），**不是只記在 set 裡** —— 模型是非同步載入的，
   第一個時段（藍）通知進來時 `_routeSets.flat` 通常還不存在，等它在 `_buildRoutes` 建好時
   再從 `_phaseT0` 把格子對回去。
   ⚠️ 少了這一步，藍色那段的格子會錨在「載入完 + 1 秒」，跟時段邊界對不起來，
   **接黃色的時候就會有一條只跑到一半就被換掉**。
2. **放不下完整一格就不換**。輪播那一行多一個 `fits` 判斷：
   `t + ROUTE_SLOT <= _phaseEnd` 才換，不然讓上一條多留一下。
   **五條變四條沒關係，有一條閃過去才難看。**

時段長度是 `js/main.js` 的 `PHASE_SECONDS`（= `COUNT_SECONDS` ÷ 階段卡片數 = 30 ÷ 3 = 10），
跟著倒數的設定自己算，改倒數秒數不用再改這裡。
只有 `set.phase` 是 true 的那一組（第一頁）吃這個判斷，首頁那組不受影響。

#### 挑下一條：洗牌袋，不是每次亂數挑

`_pickRouteInSet()` 把所有動線**洗成一輪（Fisher–Yates）、一條一條發完再洗下一輪**，
而且下一輪的第一條不會等於上一輪的最後一條（`_shuffledBag(n, avoidNext)`）。兩個保證：

1. **永遠不會連兩次同一條**
2. **每 n 條就一定把每條都跑過一次** —— 五條動線、一個時段五格，所以一個時段剛好把五條各跑一次

⚠️ 這裡以前是「亂數挑、避開最近兩條」。那樣**不保證第 2 點**：實測一個 10 秒時段裡
會出現 `0 1 4 3 1` 這種同一條跑兩次、另一條完全沒出現的情況，看起來就是「又是剛剛那條」。
⚠️ 袋子是 `pop()` 取的，所以**陣列最後一個才是下一條** —— 要避開的是它，不是第 0 個。

`set.recent` 只剩首頁按按鈕的 `playRoute()` 那條路徑在用（那邊要避開「目前這一條」，規則不一樣）。

### 參考線（跨頁共用）

畫面左邊和上邊各有一條尺規，**從尺規往內拖**就拉出一條參考線（左尺規＝垂直線、上尺規＝水平線）。

### 固定 3D 視角

⚠️ **第一頁（黃金30秒）的鏡頭是鎖死的** —— `SCENE_VIEWS.flat.lock = true` → `viewer.setCameraLock(true)`，
滑鼠完全不能轉／縮放／平移。它是固定俯視，現場手滑一下就轉走而且回不來；
而且**接近正俯視是 OrbitControls 的極點**，在那附近拖一點點就會甩很大。
編輯模式按「調整模型／調整軸心」期間會 `freeCamera(true)` 暫時放行，調完照樣存得起來。

存的視角是**偏離正上方 3 度**的俯視（`layout.json` 的 `view.pos`），樓梯落在畫面下方。
⚠️ **不要存成正上方**（`pos` 的 x/z 和 `target` 完全一樣）：那是球座標的奇異點，
OrbitControls 會把方位角正規化成 0，畫面的旋轉方向等於是隨機的，樓梯朝哪一邊都有可能。
現在這個角度是算出來的 —— 把鏡頭放在「樓梯相對於目標點的水平方向」上，樓梯就會落在畫面下方。

模型預設會自己慢慢轉。要把它定在某個角度和放大倍率，在編輯模式用工具列右邊那一排：

| 按鈕 | 說明 |
| --- | --- |
| **調整模型** | 按下去之後覆蓋層放行滑鼠，可以直接拖 3D 畫面轉角度、右鍵平移、滾輪縮放。**放開滑鼠就自動記住**（物件的操作框會暫時停用）。再按一次回到物件編輯。**這段期間自動旋轉／擺動會暫停**，不會邊拖邊被鏡頭拉走（暫停不影響存檔裡的開關） |
| **調整軸心** | 拖曳畫面平移黃色軸線＝移動自動旋轉的中心 |
| **自動旋轉** | 要不要讓模型自己轉整圈。亮起＝開 |
| **來回擺動** | 來回擺動而不轉整圈。沒鎖 A/B 時＝「目前角度 ± 擺幅」；鎖了 A/B 就在那兩個視角之間來回 |
| **速度** | 轉／擺的快慢（往左為反向、中間為停）。**刻度是非線性的**（位置平方後才是速度），慢速那端解析度才夠 —— 線性刻度下 0~0.3 只佔幾個像素，根本調不準。旁邊會顯示實際週期：擺動是「幾秒一趟」、自轉是「幾秒一圈」 |
| **擺幅** | 「目前角度 ± 幾度」。**鎖定 A/B 之後這支會自動停用**（用不到了） |
| **設 A** / **設 B** | 把目前鏡頭記成擺動的起點／終點。**Shift + 點擊**＝鏡頭跳過去看那一端在哪（會順便暫停擺動） |
| **清除 AB** | 清掉兩端，擺動回到「目前角度 ± 擺幅」 |
| **擺向** | 鎖了 A/B 之後，**去程要繞哪一邊**：`最短`（自動挑近的）／`順時針`／`逆時針`。按一下循環切換。沒鎖 A/B 時停用（那種擺動本來就對稱） |
| **狀態**（下拉，只有首頁有） | 要編輯哪一個狀態：待機（藍）／動線1~5／通關（綠）。**切過去畫面就會變成那個狀態的樣子**（配色、外觀、鏡頭、運鏡）。設過的選項後面有 ● |
| **設定 / 預覽 / 清除** | 把目前的鏡頭和運鏡存成這個狀態／把畫面切成它存好的樣子／清掉（待機的「清除」＝視角回場景預設） |
| **重設視角** | 丟掉存下來的視角，回到該場景的預設（沒存過時是停用的） |

#### 把擺動鎖在兩個視角之間

想要「就在這兩個角度之間來回」的話：

1. 按 **調整模型**，轉到第一個想要的角度 → 按 **設 A**
2. 繼續轉到第二個角度 → 按 **設 B**（這時「擺幅」會自動停用，代表已經鎖定）
3. 按 **來回擺動** 開起來，再按一次 **調整模型** 離開，就會看到它在 A、B 之間來回

**角度、俯仰、遠近、旋轉軸心四樣都會一起內插** —— 所以 A 拉遠一點、B 拉近一點也可以，
會邊轉邊推近。水平角度走比較短的那一邊，不會繞遠路。
兩端用餘弦內插（`(1-cos)/2`），到 A、B 的時候會自然減速再折回來，不是硬轉向。

**繞哪一邊**：預設走最短邊。A、B 差得比較遠時（例如 90°），你可能想要它繞另外那 270° 過去 ——
按工具列的「擺向」切成順時針或逆時針就好。順／逆是**由上往下看**的方向，
如果轉向跟你想的相反，切另一個即可。回程是原路折返（來回擺動本來就是這樣）。

擺動一趟要幾秒直接看滑桿旁邊的讀數。參考值：滑桿 1.0 ＝ 3.5s/趟、0.5 ＝ 14s、0.25 ＝ 56s、0.1 ＝ 349s。

視角是**每個場景各自一份**（第一頁的 `flat` 和首頁的 `tower` 互不影響），跟著該頁的版面存在
`layout.json` / `layout-home.json` 的 `view` 欄位裡
（`{pos, target, autoRotate, speed, swing, swingAmp, swingA, swingB}`，A/B 各是一組 `{pos, target}`）。
場景的預設值在 `js/viewer.js` 最上面的 `SCENE_VIEWS`。

#### 每條動線、通關各自的鏡頭（分鏡 + 時間軸）

首頁的「展示／切換逃生動線」跑到哪一條，就用哪一條的運鏡。
**每條動線可以沿著行徑進度放好幾個鏡頭**，鏡頭就會跟著人走。

選到「動線N」時，工具列下面會出現一條**時間軸**：

```
動線1  ●───────◆──────────────◆────────●   2.35s  [在此設鏡頭] [刪除這點] [預覽]
       0s                           6.49s   ← 這條動線自己的總秒數
```

| 操作 | 動作 |
| --- | --- |
| 拖軌道 | 沿著動線移動時間 —— **3D 裡的動線會畫到那個進度、線頭的逃生小人跟著走**，鏡頭也會跳到該時間點的運鏡 |
| **在此設鏡頭** | 把目前鏡頭記在這個時間點（同一點附近會覆蓋） |
| 拖菱形 | 改那個鏡頭點的時間 |
| 雙擊菱形 / **刪除這點** | 刪掉（刪除這點＝刪離目前時間最近的那個） |
| **預覽** | 從頭把這條動線和運鏡完整跑一次 |

典型做法：拖到 0s → 按「調整模型」轉到起點的角度 → **在此設鏡頭**；
拖到 2.5s → 轉到中段的角度 → **在此設鏡頭**；拖到 5s → 出口的角度 → **在此設鏡頭**。

- 時間存的是 **0~1 的進度**不是秒數，所以改 `ROUTE_SPEED`（或換動線資料）之後，關鍵影格不用重設，
  只是同一個點對應到的秒數會跟著變。
- 每一段之間是**球座標內插**（角度／俯仰／距離一起），段與段之間 smoothstep，經過鏡頭點會稍微放慢、不會有折角。
- 動線開始播的**前 0.8 秒**（`SHOT_FLY`）會從按下按鈕當下的鏡頭平順接進運鏡，不會硬切。
- 只放**一個**鏡頭點＝整條動線都用那個固定機位（就是原本的行為）。
- **沒設過任何鏡頭點的動線＝不動鏡頭**，維持原本的擺動；只設一部分也可以，
  跑到沒設的那條會飛回原本的視角，不會卡在上一條的鏡頭。
- **鏡頭是「停 → 轉 → 停」**：在每個關鍵影格停 `CAM_HOLD` 秒，中間滑過去。
  滑的時候走的是**通過關鍵影格的平滑曲線**（Catmull-Rom）而不是折線，並用弧長重新參數化，
  所以同一段裡不會忽快忽慢；每一段自己 ease in/out，停→動→停才不會抽動。
- **點和鏡頭是各走各的**：點照時間等速跑完整條，鏡頭照自己的時間表停停走走。
- 「通關」不是時間性的，所以沒有時間軸，用工具列的 **設定 / 預覽 / 清除** 就好。
- 開著時間軸的期間會**暫停擺動和自動旋轉**（不影響存檔的開關），離開編輯模式就恢復。

存在 `layout-home.json` 的 `view.shots`（`{route1…route5, clear}`；每個是 `{keys:[{t,pos,target}…]}`，t 是 0~1 的進度。舊格式的單一 `{pos,target}` 也還讀得到，會當成 t=0 的一個點）。

Console 也能直接設：`__viewer.setShotKey('route1', 0.5)`、`__viewer.shotKeys('route1')`、`__viewer.gotoShotAt('route1', .5)`、`__viewer.previewRouteAt('tower', 0, .5, 'route1')`、`__viewer.setShot('clear')`、`__viewer.playShot('clear')`、
`__viewer.releaseShot()`、`__viewer.listShots()`、`__viewer.clearShot('route1')`，
以及 `__viewer.setSwingRange(a, b)`、`__viewer.setSwingEnd('a')`、
`__viewer.gotoSwingEnd('b')`、`__viewer.clearSwingRange()`（設完記得進編輯模式存檔，或自己 `saveView`）。

### 對齊與均分

工具列中間有三組圖示按鈕（滑過去有中文說明），用 `Shift` + 點擊多選之後最好用：

| 組 | 按鈕 | 說明 |
| --- | --- | --- |
| 對齊 | 靠左 / 水平置中 / 靠右 / 靠上 / 垂直置中 / 靠下 | **選 2 個以上**＝以選取範圍的外框為基準互相對齊；**只選 1 個**＝直接對齊到整個版面 |
| 均分 | 水平均分 / 垂直均分 | 頭尾不動，中間重排成**間距相等**（需選 3 個以上，不足會停用） |
| 整組置中 | 水平 / 垂直 | 把選取的東西當成一整組搬到畫面正中，組內相對位置不變 |

按鈕會依選取數量自動停用。所有操作都吃 `Ctrl+Z`。

Console 也能操作：`__editors.first.select('act1'); __editors.first.select('act2', true)`（第二個參數 = 加選）。

### 存檔

改完會**同時存兩份**：

1. `layout.json`（專案資料夾裡的檔案，由 `server.mjs` 的 `PUT /layout.json` 寫入）
2. `localStorage`（key `fire30.layout`）

讀取時**檔案優先**，沒有檔案才退回 `localStorage`。所以就算瀏覽器用無痕模式、或設定成關閉時清除網站資料，
版面也不會消失；換一台電腦、換一個瀏覽器開也讀得到同一份。用純靜態主機（不支援 PUT）開的話寫檔會失敗，
console 會印一次警告，然後照舊只存 `localStorage`。

「全部重設」和 `__editor.reset()` 會把檔案和 `localStorage` 一起清掉。

座標是以 `rem` 儲存的，所以換螢幕解析度仍會等比縮放。還沒動過任何東西之前，視窗尺寸一變就會自動重新量一次，不會卡在舊尺寸。

⚠️ 版面是**照你編輯當下的視窗比例**存的。如果之後用差很多的比例開（例如從 16:9 換成直式），
自訂位置不會自己重排，需要重新調整，或按「全部重設」回到自動排版。

**壞掉的存檔會自動丟掉**：套用後如果有三成以上的物件跑到畫面外，就判定這份存檔和目前視窗對不起來，
直接忽略、刪掉存檔、回到自動排版，並在 console 留一行警告。
不然畫面會整個歪掉又不知道怎麼救。手動要跳過存檔看原始排版的話，網址加 `?layout=off`。
直式版面下 `.stage` 是 `display:none`，編輯器會自動跳過沒被排版到的物件，不會把它存成 0×0。

**要固定成程式碼**：按「複製 JSON」拿到版面資料，之後用 `__editor.set(<貼上的JSON>)` 套用，或直接把數值寫回 CSS。

**要加新物件進編輯清單**：在 `index.html` 該元素加上 `data-obj="唯一代號" data-label="顯示名稱"` 即可，編輯器會自動接手。

**存檔和視窗尺寸對不起來時**（`looksSane()`：套用後有超過 3 成的物件掉到畫面外）：
**這一次**回到自動排版，並在 console 留一則警告，**但存檔不會被刪掉** ——
視窗常常只是暫時比較小（縮視窗、預覽窗格、接了別的螢幕），把尺寸調回去就會自己套回來。
⚠️ 這裡以前是直接 `DELETE` 掉版面檔的，等於「縮一次視窗就把使用者排好的版面永久毀掉」，
而且完全看不出是什麼時候沒的。忽略是可逆的，刪除不是 —— 不要改回去。
真的要清掉版面請走側欄的「重設」（那支才會 DELETE）。

**要讓新的一頁也能編輯**：在 `js/main.js` 的 `editors` 加一個實例（給不同的 `storageKey` / `layoutUrl`），
再到 `css/editor.css` 把那頁的排版容器加進 `.is-edited .layout, .is-edited .home{…}` 那條規則。

⚠️ 排版容器**一定要在 `.is-edited` 時改成 `display:block`**。grid 容器裡絕對定位的項目，
如果還帶著明確的 `grid-area`，它的容器塊會是「那一格」而不是整個容器，`left/top` 就會算成相對於格子、位置整個歪掉。

**清掉所有調整**：console 執行 `__editor.reset()`，或網址加 `?layout=off` 開一次（只是這次不套用，不會刪存檔）。

## 載入畫面

`<html>` 上直接寫了 `class="is-booting"`（不是靠 JS 加，這樣第一次繪製前就生效），
畫面會是一整片深藍 + 淡淡的「載入中」，等自訂版面套用完 `main.js` 才把它拿掉。
使用者不會看到「先跳出預設版面、再瞬間跳成自訂版面」的過程。

- 遮罩用 `opacity` 不用 `visibility` —— `visibility` 會被子層的 `.page.is-active{visibility:visible}` 蓋回來。
- 「載入中」有 0.7 秒的延遲才淡入，秒開時不會閃一下字。
- 另外設了 4 秒的保險，就算字體或版面讀取失敗也一定會顯示畫面。

## 主色調

預設 **藍色**。整組配色集中在 `css/style.css` 最上方，3D 場景也讀同一組變數。

| 做法 | 用法 |
| --- | --- |
| 網址 | `?theme=green` / `?theme=blue` / `?theme=red` |
| Console | `__setTheme('green')`（會記在 localStorage，也是離開首頁動線示範後要回去的那一個） |
| 寫死 | `js/main.js` 的 `setTheme(... ?? 'blue')` |

要調成別的顏色，只改 `:root` 那一區的 `--brand` / `--brand-hi` / `--bg-*` / `--m-*` 即可，其他都是引用。
（`--m-shade` 是通關「整棟變白」時底部的陰影色，只有那個畫面會用到。）
`--amber`（警語）、`--red`（起火點）、`--exit`（安全出口綠）屬語意色，不隨主題變動。

紅色那一組平常不會用到，是首頁「展示／切換逃生動線」跑動線的那幾秒在用的（抵達出口再換成綠色）。

## 面板樣式

階段卡、四格應對、底部警語都用 `.chamfer`（`css/style.css` 最上面）：**內部不填色，只有一圈漸層細框**，四角倒角。

| 變數 | 作用 |
| --- | --- |
| `--ch` | 倒角大小（階段卡 `.7rem`、四格與警語 `.5rem`，設 `0` 變回直角） |
| `--bw` | 框線粗細（預設 `.5px`，階段卡亮起時 `.75px`） |
| `--stroke` | 框線的漸層，預設由 `--brand-hi` 往 `--brand` 淡出再回升 |
| `--glass` | 內部底色，預設 `none`；只有階段卡填了一層很淡的高光漸層 |

作法：`--ring` 用 `clip-path: polygon(evenodd, 外框…, 內孔…)` 一次畫出中空的八邊形環，
`--shape` 則是同樣尺寸的實心八邊形。兩個偽元素分工：

- `::before` = 玻璃層，套 `--shape` + `--glass`，階段卡再加 `backdrop-filter:blur(7px)`
- `::after` = 框線層，套 `--ring` + `--stroke`

`--ci` 是內孔倒角的起點，往內縮了 `0.5858 × --bw`，斜邊才會和直邊一樣粗。

`--ring` 的點列裡，外圈最後補一次起點、內圈最後也補一次起點 —— **兩圈都要各自閉合**。
少了這兩個補點，外圈的左緣會被當成連往內圈的連接段跳過，框線就會缺左邊那一條。
中間那段「外圈起點 → 內圈起點」和收尾的「內圈起點 → 外圈起點」完全重疊，會互相抵銷，不影響填色。

框線細到 `.5px` 之後會被抗鋸齒吃掉約一半濃度，所以 `--stroke` 的透明度是加倍後的值；
最暗的那一段也留了下限，否則右下角會淡到看不見、看起來一樣像缺一條邊。

兩個要注意的地方：

- **底色和框線都畫在偽元素上，不能畫在元素本身** —— `clip-path` 會連同子元素一起裁切，畫在元素上會把內容裁掉。
- 內容要靠 `.chamfer > *{z-index:1}` 浮在兩層之上，所以**直接子元素不能是純文字節點**（要包成元素）。

### 階段卡亮起

三段各有自己的 `--hot`，色值集中在 `:root` 的 `--stage-0/1/2`，**倒數圓盤和階段卡共用同一組**：

| 段 | 剩餘秒數 | 顏色 |
| --- | --- | --- |
| `0-10` 秒 | 30–21 | 藍 `--stage-0`（= `--brand-hi`，跟著主色走） |
| `10-20` 秒 | 20–11 | 黃 `--stage-1` `#ffb42e` |
| `20-30` 秒 | 10–0 | 紅 `--stage-2` `#ff4a3d` |

`countdown.js` 會把時段寫成 `.timer` 上的 `data-stage`，圓盤的**大數字**、刻度、指標點、「秒」、
「黃金逃生時間」、「把握 30 秒」的數字、彗星光帶全部讀同一個 `--hot`，所以三個顏色只要改 `:root` 那三行。

剩下 5 秒以內時 `countdown.js` 會在 `.timer` 加上 `.is-urgent`，大數字用 `urgentBlink` 閃爍
（一秒一次，透明度 1 ↔ 0.22，光暈同步收放）。門檻改 `createCountdown({ urgentAt: 5 })`。

輪到時整張卡都換成該段的 `--hot`：

| 部位 | 變化 |
| --- | --- |
| 框線 | `--stroke` 換成 `--hot`、`--bw` `.5px`→`.75px`，`::after` 加 `drop-shadow` 讓只有框在發光 |
| 玻璃層 | `--glass` 混入一點 `--hot` |
| 圓形 Icon | 邊框、圖示、內外光暈都換成 `--hot` |
| 標題（0-10 秒） | 直接變 `--hot`，另加一圈 `text-shadow` |
| 說明文字 | `color-mix(--hot 42%, --ink)`——帶一點色調並提亮，保留可讀性 |

排版不動（只有整張卡左移 `.35rem` 當位置提示）。

## 倒數圓盤的彗星光帶

內圈（SVG viewBox 裡 `r=118` 那一圈）上有一道**逆時針、兩秒轉一圈**的光帶，`css/style.css` 的 `.comet`，顏色跟著 `--hot` 走。

作法是 `conic-gradient` 沿圓周淡出當尾巴，再用 `mask: radial-gradient(closest-side, …)` 把中間挖空只留最外緣一圈，
最後 `animation: cometSpin 1s linear infinite`。外層 `.comet` 只負責 `drop-shadow`——
光暈要打在外層，否則會套在「還沒遮罩」的整個圓盤上。

| 想改 | 改哪裡 |
| --- | --- |
| 速度 | `.comet i` 的 `animation` 時間（目前 `2s`） |
| 方向 | `@keyframes cometSpin` 的角度正負（`-360deg` = 逆時針）。**改方向時尾巴的漸層也要跟著鏡射**，否則尾巴會跑到頭前面 |
| 粗細 | `.comet` 的 `--r`（目前 `.34rem`） |
| 尾巴長度／濃度 | `conic-gradient` 的色標，角度越大離頭越遠 |
| 半徑 | `.comet` 的 `width`（`59%` = viewBox 的 `r=118`） |

已加 `prefers-reduced-motion` 的關閉規則。

## 放 3D 模型

三種方式，任選：

1. **拖曳**：把 `.glb` / `.gltf` 直接拖到左側模型框。
2. **網址參數**：`index.html?model=./models/xxx.glb`
3. **寫死**：在 `js/main.js` 最下方加 `load('./models/xxx.glb')`。

模型載入後會自動置中、依尺寸調整相機距離；沒有模型時顯示內建的示意平面圖（起火點 + 逃生動線 + 安全出口）。

支援 Draco 壓縮（decoder 走 CDN）。
