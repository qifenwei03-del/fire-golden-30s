# 火災黃金30秒 — THE GOLDEN 30 SECONDS

Three.js 展場網頁。兩頁：**火災黃金30秒**（倒數）與**首頁**（逃生動線示範）。

## 開機流程

開機停在「火災黃金30秒」當歡迎頁，**倒數跑完一輪（30 秒）自動進首頁**。

- 只會自動跳這一次。手動切過頁之後就不再干涉，按 `Esc` 回黃金30秒不會又被跳走。
- 正在編輯版面（`E`）時不會跳，離開編輯模式後的下一輪才會。
- 要改流程改 `js/main.js` 最上面的 `WELCOME_FROM` / `WELCOME_TO`；不想自動跳就把
  `createCountdown` 的 `onEnd` 拿掉。

## 首頁（ENTER）

標題「雲端宅邸」、左側 3D 區、右側**逃生動線示範**的兩顆按鈕、
左下三個功能鍵（立即警報 / 逃生路線 / 安全法規）、右下大樓標語。

右下角的大樓名稱和標語條互相置中（不是靠右對齊）。兩者都用 `padding-left` 補掉字距在尾端多出來的空白，
不然中文加了 `letter-spacing` 之後看起來會偏左。

右下的 `[新大樓名稱]` 是佔位字，換成實際大樓名請改 `index.html` 的 `.home__guide-name`。
左下三個功能鍵目前是 `<button>` 但**還沒接任何行為**，只有 hover／focus 樣式。

### 逃生動線示範（右側兩顆按鈕）

原本的歡迎／登入面板已經拿掉，換成 **展示逃生動線** 和 **切換逃生動線**。兩顆按的流程完全一樣：

1. 整個介面切成**紅色主題**（`?theme=red` 那一組）
2. 隨機挑一條逃生動線，**依它的長度換算秒數**（固定行走速度）從紅色起點沿折線畫到綠色出口
   （線頭有一顆白色亮點跟著跑）；
   **這條動線有設過機位的話，鏡頭會用 0.8 秒平順飛過去並停在那裡**
3. 抵達出口 → **3D 黑掉**（版面上的字和按鈕留著）→ 介面切成綠色主題、路線收掉、整棟建物變成白色實心、鏡頭直接就定位 → 亮起來，跳出「**恭喜通關**」

**狀態切換一律用黑幕，不用鏡頭飛過去銜接**（黑 0.22 秒 → 換好 → 亮起來）。
飛過去的話鏡頭會從動線的角度硬轉到通關的角度，很怪；黑掉直接就定位乾淨得多。

**只黑 3D 那一塊**，標題、按鈕、標語、恭喜通關都不會跟著消失 ——
黑幕（`index.html` 的 `.blackout`）是放在 `.home__stage` 裡面的，`z-index:2` 疊在 canvas 上、
在舞台標籤（`z-index:3`）下面。時間在 `js/main.js` 的 `FADE_OUT`，要和 CSS 的 transition 一致。

**動線上的點照路徑長度等速跑**：秒數 = 路徑長度 ÷ `ROUTE_SPEED`，所以每條的點速度都一樣（6.4 單位/秒），
不會忽快忽慢。目前五條約 **5.7 ~ 7.1 秒**。編輯模式的時間軸會顯示該條自己的總秒數。

**鏡頭不跟著點跑**：它會在**每個關鍵影格停 `CAM_HOLD` 秒（預設 0.25）**，然後滑到下一個影格，
到了再停。所以鏡頭是「停 → 轉 → 停 → 轉 → 停」，不是一路連續掃過去。
剩下的時間按「這一段鏡頭要走多遠」分給各段，每一段自己加減速。
**鏡頭和點不會完全對齊**，這是刻意的取捨（要對齊就得讓點忽快忽慢）。

「整棟變白」是把半透明玻璃牆板換成白色樓板那組材質（`--m-slab`、不透明），
並套一層**由上往下的陰影漸層**：上面是 `--m-slab`、下面壓到 `--m-shade`，
自發光也從平常的 .35 降到 .07 —— 不然整棟自己在發光，會亮得很均勻、看不出立體感。
離開通關狀態就換回玻璃。

| 想調 | 改哪裡 |
| --- | --- |
| 陰影是什麼顏色 | `css/style.css` 各主題的 `--m-shade`（藍 `#4d6a86` / 綠 `#3f7d63` / 紅 `#8a544c`） |
| 陰影吃掉多少高度 | `js/viewer.js` 最上面的 `SHADE.span`（`0.55` = 下面 55% 是漸層，上面維持白） |
| 整體要更深 / 更亮 | `SHADE.emissive`（`0.07`；**越大底部越亮、層次越平**，設 0 就完全靠打光） |

漸層是**頂點色**做的（依世界座標的高度算），算好會快取在 geometry 上，只有換主題才重算。
所以 `--m-slab` / `--m-shade` 改了會自動跟著變，不用重跑模型前處理。

### 待機時的起火點（紅色閃點 + 紅色煙霧）

待機（藍）時會挑**離鏡頭最近**的那一條動線的起點當起火位置，在那裡放一顆閃爍的紅點，並冒出紅色煙霧。
**不會畫路徑** —— 路徑要按了按鈕才出現。

模型在擺動／自轉的時候，起火點會**跟著轉到面前的那一條換**（轉到離動線1 比較近就換成動線1 的起點）。
每 0.2 秒重挑一次，而且要近一成以上才換，兩點差不多時才不會一直跳。

- 按下按鈕就跑**正在冒煙的那一條**（看到哪裡起火就從哪裡逃）。之後再按才是隨機換別條。
- 煙霧是**卡通風**的：9 顆雲朵狀的 sprite，一顆一顆「啵」地彈出來，邊飄邊轉（一輪 2.6 秒）。
  形狀是**下小上大**（大小 0.8 → 4.0）、顏色**下紅上透**（濃度 0.78 → 0.10），像一柱往上散開的煙。
  貼圖是 canvas 畫的**雲朵剪影**（六個圓的聯集），邊緣是硬的、分成「深外圈 + 亮內裡」兩層，賽璐珞感。
  顏色吃 `--red`（語意色，不隨主題變）。
  
  | 想調 | 改哪裡（`js/viewer.js`） |
  | --- | --- |
  | 幾顆、多大、飄多高多散、幾秒一輪 | `_makeSmoke()` 的 `count` / `size` / `rise` / `spread` / `life` / `opacity` |
  | 雲朵長什麼樣、外圈多深 | `smokeTexture()` 的 `puffs` 座標和 `fill(1.00, 0.5)` / `fill(0.86, 1.0)` 兩層 |
  | 彈出來的力道 | `_updateSmoke()` 裡 `age < 0.18` 那段回彈曲線 |
- 編輯模式選「待機（藍）」也會顯示，選動線或通關就收掉 —— 看到的跟實際跑起來一樣。

### 七個狀態的運鏡各自獨立

**待機（藍）／動線1～5（紅）／通關（綠）** 共七個狀態，每一個都能單獨設定「鏡頭」和「運鏡」，互不影響。
動線是**五條隨機抽**（避開剛剛那一條），不顯示關卡編號。

每個狀態可以存兩樣東西，組合出四種行為：

| 這個狀態存了什麼 | 跑起來的樣子 |
| --- | --- |
| **兩個以上鏡頭點**（時間軸） | 鏡頭沿著行徑進度走（見下面的時間軸） |
| **一個鏡頭點** | 飛過去停在那裡不動 |
| **一個鏡頭點 + 運鏡** | 飛過去，然後照那個運鏡（例如自己轉、來回擺） |
| **只有運鏡、沒有鏡頭點** | 鏡頭留在原地，直接套那個運鏡 |
| **什麼都沒設** | 回到待機的視角和運鏡（藍色那組） |

「運鏡」＝自動旋轉／來回擺動／速度／擺幅／A B 這一整組。程式裡七個狀態共用 `viewer.enterState()` 判斷。

#### 怎麼設

編輯模式（`E`）→ 工具列的「**狀態**」下拉選要編的那一個。**切過去畫面就會整個變成那個狀態的樣子**
（配色、建物外觀、鏡頭、運鏡都會跟著換），所以你看到什麼就是跑起來的樣子：

| 選到 | 畫面會變成 |
| --- | --- |
| 待機（藍） | 藍色主題 + 玻璃牆 + 存好的待機視角與擺動 |
| 動線1~5 | **紅色主題** + 該條動線的時間軸與運鏡 |
| 通關（綠） | **綠色主題 + 整棟變白** + 通關的機位與自動旋轉 |

調好之後按「**設定**」存起來（待機存視角、動線存運鏡、通關存鏡頭+運鏡）。
離開編輯模式會自動切回待機的配色。

通關（綠）沒設過的話，預設是原地慢慢轉（`js/main.js` 的 `GREEN_MOTION`）。

再按任何一顆就換一條重跑（會避開剛剛那一條）。**離開首頁**（`Esc` / `0` / `1`）會收掉動線、
關掉通關訊息、主色回到使用者原本選的那一個（預設藍）。通關訊息在按下一次按鈕或離開首頁之前會一直留著。

| 想改 | 改哪裡 |
| --- | --- |
| 點走多快 | `js/main.js` 的 `ROUTE_SPEED`（目前 `6.4`；**數字越小走越慢**，秒數會跟著變長） |
| 鏡頭在每個影格停多久 | `CAM_HOLD`（目前 `0.25` 秒；設 `0` 就一路滑過去不停） |
| 秒數上下限 | `ROUTE_SECONDS`（目前 `[3, 12]`，避免極端長度的動線跑到天荒地老） |
| 紅／綠是哪兩組色 | `js/main.js` 的 `setTheme('red')` / `setTheme('green')`，色值在 `css/style.css` 的 `:root[data-theme=...]` |
| 動線本身 | `models/routes-home.json`（5 條，由 `tools/extract-home.mjs` 從 BIM 的逃生動線圖抽出，細節見 `HANDOFF.md` 0.4） |
| 通關訊息 | `index.html` 的 `.home__clear`，樣式在 `css/style.css` 的 `.home__clear*` |
| 狀態切換的黑幕 | `js/main.js` 的 `FADE_OUT`（`220`，要和 `css/style.css` 的 `.blackout` transition 一致） |
| 通關時整棟變白的樣子 | `js/viewer.js` 的 `_applyWallLook()` |

底層是 `viewer.playRoute('tower', {duration, avoidCurrent, onDone})`、`viewer.stopRoute('tower')`、
`viewer.playShot(name, 秒)` / `viewer.releaseShot(秒)`、`viewer.setAllWhite(true|false)`。
首頁那一組動線是 **manual 模式**（平常全部藏著、只有按按鈕才播）；第一頁仍是 auto 模式（每 2 秒自己換一條）。

### 首頁的 3D 模型（真實 BIM）

`models/tower.glb` 是 `tools/restyle-tower.mjs` 從 Revit 匯出的 `標準層三層.gltf`（路徑寫在腳本最上面的 `IN`）
前處理出來的。**分類是依幾何形狀**，收斂成三個具名材質：

| 材質名 | 怎麼判定 | 執行期長相 |
| --- | --- | --- |
| `slab` | 很扁很寬的**樓板**（dy < 0.6 且水平投影 > 全棟 15%），加上節點名含「**樓梯**」的整個子樹 | 白色實心（帶一點自發光）+ 1° 整圈框線 |
| `wall-cut` | 近側兩面外牆（東 +X、南 +Z） | **隱藏**（剖面挖掉，才看得進室內） |
| `wall` | 其餘全部（牆、柱、窗框、家具…） | 半透明玻璃牆板（opacity .28、雙面、不寫深度）+ 30° 結構框線 |

**材質名稱是離線與執行期之間唯一的橋樑**（`js/viewer.js` 的 `_styleBlueprint` 只認名字）。

> 中間曾改成「依來源材質透不透」分類（透→玻璃、不透→白），試過之後決定改回這一版。原委見 `HANDOFF.md` 0.9。

重跑前處理（來源 49MB，記得加大 heap）：

```bash
npm i @gltf-transform/cli
node --max-old-space-size=6144 tools/restyle-tower.mjs
node_modules/.bin/gltf-transform optimize restyled.gltf models/tower.glb --compress draco --texture-compress false --simplify false
```

3D 場景和第一頁**共用同一顆 renderer**（`viewer.mount()` 把 canvas 搬到當前頁的容器），但**佔位模型不同**：

| 頁 | 場景 | 內容 |
| --- | --- | --- |
| 火災黃金30秒 | `flat` | 單層平面圖 |
| 首頁 | `tower` | 三層疊起來的大樓（半透明樓板 + 隔間，起火點在頂樓、出口在一樓，逃生動線沿樓梯間往下） |

兩組場景都建在 `modelRoot` 底下，用 `viewer.setScene('flat' | 'tower')` 切 `visible`，同時把鏡頭挪到該場景的預設位置
（`SCENE_VIEWS`，在 `js/viewer.js` 最上面，可以改鏡頭角度、距離與霧氣範圍）。
樓層數和樓距在 `_buildTower()` 的 `FLOORS` / `FH`。
樓板顏色是 `--m-slab`（偏藍的白，藍綠兩個主題各有一組），材質帶一點自發光，陰影裡才不會變灰。

拖 `.glb` 進來或用 `?model=` 載入外部模型時，兩個佔位場景都會被清掉、換成那一個模型（兩頁共用）。

⚠️ 在輸入欄位裡打字時全域快捷鍵會停用（編輯模式工具列有數字輸入框），`Esc` 在欄位裡是離開欄位、不是切頁。

### 參考線（跨頁共用）

畫面左邊和上邊各有一條尺規，**從尺規往內拖**就拉出一條參考線（左尺規＝垂直線、上尺規＝水平線）。

**參考線是所有頁共用的一份**——在哪一頁拉的線，每一頁都看得到，方便跨頁對齊。
顏色代表它是從哪一頁拉出來的：

| 來源頁 | 顏色 |
| --- | --- |
| 火災黃金30秒 | 青 `#25e6c0` |
| 首頁 | 橘 `#ff9b3d` |

| 操作 | 動作 |
| --- | --- |
| 拖參考線 | 移動，會吸附到物件的邊 / 中線與版面中線；拖曳時顯示 px 座標 |
| 拖回尺規 | 線變紅色＝放開就刪除 |
| 雙擊參考線 | 刪除 |
| 工具列「清除參考線」 | 全部刪掉（所有頁） |

任何一頁都能移動或刪除別頁拉出來的線（顏色會保留，代表出身）。物件移動時會一併吸附到參考線。
參考線存在 `layout-guides.json`（和 `localStorage` 的 `fire30.guides`），和各頁的物件版面分開存，以 `rem` 記錄。
「全部重設」只重設該頁的物件，不會動到參考線。

早期版本把參考線存在各頁的版面檔裡（只有數字、沒有來源頁），
載入時會自動搬到共用清單並補上來源頁（就是那個版面檔所屬的頁），搬完會把舊欄位清掉，只跑一次。

工具列可直接輸入 X / Y / 寬 / 高 / 縮放的精確數值，另有「隱藏 / 清除參考線 / 複製 JSON / 全部重設 / 離開」。

### 固定 3D 視角

模型預設會自己慢慢轉。要把它定在某個角度和放大倍率，在編輯模式用工具列右邊那一排：

| 按鈕 | 說明 |
| --- | --- |
| **調整模型** | 按下去之後覆蓋層放行滑鼠，可以直接拖 3D 畫面轉角度、右鍵平移、滾輪縮放。**放開滑鼠就自動記住**（物件的操作框會暫時停用）。再按一次回到物件編輯。**這段期間自動旋轉／擺動會暫停**，不會邊拖邊被鏡頭拉走（暫停不影響存檔裡的開關） |
| **調整軸心** | 拖曳畫面平移黃色軸線＝移動自動旋轉的中心 |
| **自動旋轉** | 要不要讓模型自己轉整圈。亮起＝開 |
| **來回擺動** | 來回擺動而不轉整圈。沒鎖 A/B 時＝「目前角度 ± 擺幅」；鎖了 A/B 就在那兩個視角之間來回 |
| **速度** | 轉／擺的快慢（往左為反向、中間為停）。**刻度是非線性的**（位置平方後才是速度），慢速那端解析度才夠 —— 線性刻度下 0~0.3 只佔幾個像素，根本調不準。旁邊會顯示實際週期：擺動是「幾秒一趟」、自轉是「幾秒一圈」 |
| **擺幅** | 「目前角度 ± 幾度」。**鎖定 A/B 之後這支會自動停用**（用不到了） |
| **設 A** / **設 B** | 把目前鏡頭記成擺動的起點／終點。**Shift + 點擊**＝鏡頭跳過去看那一端在哪（會順便暫停擺動） |
| **清除 AB** | 清掉兩端，擺動回到「目前角度 ± 擺幅」 |
| **擺向** | 鎖了 A/B 之後，**去程要繞哪一邊**：`最短`（自動挑近的）／`順時針`／`逆時針`。按一下循環切換。沒鎖 A/B 時停用（那種擺動本來就對稱） |
| **狀態**（下拉，只有首頁有） | 要編輯哪一個狀態：待機（藍）／動線1~5／通關（綠）。**切過去畫面就會變成那個狀態的樣子**（配色、外觀、鏡頭、運鏡）。設過的選項後面有 ● |
| **設定 / 預覽 / 清除** | 把目前的鏡頭和運鏡存成這個狀態／把畫面切成它存好的樣子／清掉（待機的「清除」＝視角回場景預設） |
| **重設視角** | 丟掉存下來的視角，回到該場景的預設（沒存過時是停用的） |

#### 把擺動鎖在兩個視角之間

想要「就在這兩個角度之間來回」的話：

1. 按 **調整模型**，轉到第一個想要的角度 → 按 **設 A**
2. 繼續轉到第二個角度 → 按 **設 B**（這時「擺幅」會自動停用，代表已經鎖定）
3. 按 **來回擺動** 開起來，再按一次 **調整模型** 離開，就會看到它在 A、B 之間來回

**角度、俯仰、遠近、旋轉軸心四樣都會一起內插** —— 所以 A 拉遠一點、B 拉近一點也可以，
會邊轉邊推近。水平角度走比較短的那一邊，不會繞遠路。
兩端用餘弦內插（`(1-cos)/2`），到 A、B 的時候會自然減速再折回來，不是硬轉向。

**繞哪一邊**：預設走最短邊。A、B 差得比較遠時（例如 90°），你可能想要它繞另外那 270° 過去 ——
按工具列的「擺向」切成順時針或逆時針就好。順／逆是**由上往下看**的方向，
如果轉向跟你想的相反，切另一個即可。回程是原路折返（來回擺動本來就是這樣）。

擺動一趟要幾秒直接看滑桿旁邊的讀數。參考值：滑桿 1.0 ＝ 3.5s/趟、0.5 ＝ 14s、0.25 ＝ 56s、0.1 ＝ 349s。

視角是**每個場景各自一份**（第一頁的 `flat` 和首頁的 `tower` 互不影響），跟著該頁的版面存在
`layout.json` / `layout-home.json` 的 `view` 欄位裡
（`{pos, target, autoRotate, speed, swing, swingAmp, swingA, swingB}`，A/B 各是一組 `{pos, target}`）。
場景的預設值在 `js/viewer.js` 最上面的 `SCENE_VIEWS`。

#### 每條動線、通關各自的鏡頭（分鏡 + 時間軸）

首頁的「展示／切換逃生動線」跑到哪一條，就用哪一條的運鏡。
**每條動線可以沿著行徑進度放好幾個鏡頭**，鏡頭就會跟著人走。

選到「動線N」時，工具列下面會出現一條**時間軸**：

```
動線1  ●───────◆──────────────◆────────●   2.35s  [在此設鏡頭] [刪除這點] [預覽]
       0s                           6.49s   ← 這條動線自己的總秒數
```

| 操作 | 動作 |
| --- | --- |
| 拖軌道 | 沿著動線移動時間 —— **3D 裡的動線會畫到那個進度、線頭亮點跟著走**，鏡頭也會跳到該時間點的運鏡 |
| **在此設鏡頭** | 把目前鏡頭記在這個時間點（同一點附近會覆蓋） |
| 拖菱形 | 改那個鏡頭點的時間 |
| 雙擊菱形 / **刪除這點** | 刪掉（刪除這點＝刪離目前時間最近的那個） |
| **預覽** | 從頭把這條動線和運鏡完整跑一次 |

典型做法：拖到 0s → 按「調整模型」轉到起點的角度 → **在此設鏡頭**；
拖到 2.5s → 轉到中段的角度 → **在此設鏡頭**；拖到 5s → 出口的角度 → **在此設鏡頭**。

- 時間存的是 **0~1 的進度**不是秒數，所以改 `ROUTE_SPEED`（或換動線資料）之後，關鍵影格不用重設，
  只是同一個點對應到的秒數會跟著變。
- 每一段之間是**球座標內插**（角度／俯仰／距離一起），段與段之間 smoothstep，經過鏡頭點會稍微放慢、不會有折角。
- 動線開始播的**前 0.8 秒**（`SHOT_FLY`）會從按下按鈕當下的鏡頭平順接進運鏡，不會硬切。
- 只放**一個**鏡頭點＝整條動線都用那個固定機位（就是原本的行為）。
- **沒設過任何鏡頭點的動線＝不動鏡頭**，維持原本的擺動；只設一部分也可以，
  跑到沒設的那條會飛回原本的視角，不會卡在上一條的鏡頭。
- **鏡頭是「停 → 轉 → 停」**：在每個關鍵影格停 `CAM_HOLD` 秒，中間滑過去。
  滑的時候走的是**通過關鍵影格的平滑曲線**（Catmull-Rom）而不是折線，並用弧長重新參數化，
  所以同一段裡不會忽快忽慢；每一段自己 ease in/out，停→動→停才不會抽動。
- **點和鏡頭是各走各的**：點照時間等速跑完整條，鏡頭照自己的時間表停停走走。
- 「通關」不是時間性的，所以沒有時間軸，用工具列的 **設定 / 預覽 / 清除** 就好。
- 開著時間軸的期間會**暫停擺動和自動旋轉**（不影響存檔的開關），離開編輯模式就恢復。

存在 `layout-home.json` 的 `view.shots`（`{route1…route5, clear}`；每個是 `{keys:[{t,pos,target}…]}`，t 是 0~1 的進度。舊格式的單一 `{pos,target}` 也還讀得到，會當成 t=0 的一個點）。

Console 也能直接設：`__viewer.setShotKey('route1', 0.5)`、`__viewer.shotKeys('route1')`、`__viewer.gotoShotAt('route1', .5)`、`__viewer.previewRouteAt('tower', 0, .5, 'route1')`、`__viewer.setShot('clear')`、`__viewer.playShot('clear')`、
`__viewer.releaseShot()`、`__viewer.listShots()`、`__viewer.clearShot('route1')`，
以及 `__viewer.setSwingRange(a, b)`、`__viewer.setSwingEnd('a')`、
`__viewer.gotoSwingEnd('b')`、`__viewer.clearSwingRange()`（設完記得進編輯模式存檔，或自己 `saveView`）。

### 存檔

改完會**同時存兩份**：

1. `layout.json`（專案資料夾裡的檔案，由 `server.mjs` 的 `PUT /layout.json` 寫入）
2. `localStorage`（key `fire30.layout`）

讀取時**檔案優先**，沒有檔案才退回 `localStorage`。所以就算瀏覽器用無痕模式、或設定成關閉時清除網站資料，
版面也不會消失；換一台電腦、換一個瀏覽器開也讀得到同一份。用純靜態主機（不支援 PUT）開的話寫檔會失敗，
console 會印一次警告，然後照舊只存 `localStorage`。

「全部重設」和 `__editor.reset()` 會把檔案和 `localStorage` 一起清掉。

座標是以 `rem` 儲存的，所以換螢幕解析度仍會等比縮放。還沒動過任何東西之前，視窗尺寸一變就會自動重新量一次，不會卡在舊尺寸。

⚠️ 版面是**照你編輯當下的視窗比例**存的。如果之後用差很多的比例開（例如從 16:9 換成直式），
自訂位置不會自己重排，需要重新調整，或按「全部重設」回到自動排版。

**壞掉的存檔會自動丟掉**：套用後如果有三成以上的物件跑到畫面外，就判定這份存檔和目前視窗對不起來，
直接忽略、刪掉存檔、回到自動排版，並在 console 留一行警告。
不然畫面會整個歪掉又不知道怎麼救。手動要跳過存檔看原始排版的話，網址加 `?layout=off`。
直式版面下 `.stage` 是 `display:none`，編輯器會自動跳過沒被排版到的物件，不會把它存成 0×0。

**要固定成程式碼**：按「複製 JSON」拿到版面資料，之後用 `__editor.set(<貼上的JSON>)` 套用，或直接把數值寫回 CSS。

**要加新物件進編輯清單**：在 `index.html` 該元素加上 `data-obj="唯一代號" data-label="顯示名稱"` 即可，編輯器會自動接手。

**要讓新的一頁也能編輯**：在 `js/main.js` 的 `editors` 加一個實例（給不同的 `storageKey` / `layoutUrl`），
再到 `css/editor.css` 把那頁的排版容器加進 `.is-edited .layout, .is-edited .home{…}` 那條規則。

⚠️ 排版容器**一定要在 `.is-edited` 時改成 `display:block`**。grid 容器裡絕對定位的項目，
如果還帶著明確的 `grid-area`，它的容器塊會是「那一格」而不是整個容器，`left/top` 就會算成相對於格子、位置整個歪掉。

**清掉所有調整**：console 執行 `__editor.reset()`，或網址加 `?layout=off` 開一次（只是這次不套用，不會刪存檔）。

## 載入畫面

`<html>` 上直接寫了 `class="is-booting"`（不是靠 JS 加，這樣第一次繪製前就生效），
畫面會是一整片深藍 + 淡淡的「載入中」，等自訂版面套用完 `main.js` 才把它拿掉。
使用者不會看到「先跳出預設版面、再瞬間跳成自訂版面」的過程。

- 遮罩用 `opacity` 不用 `visibility` —— `visibility` 會被子層的 `.page.is-active{visibility:visible}` 蓋回來。
- 「載入中」有 0.7 秒的延遲才淡入，秒開時不會閃一下字。
- 另外設了 4 秒的保險，就算字體或版面讀取失敗也一定會顯示畫面。

## 主色調

預設 **藍色**。整組配色集中在 `css/style.css` 最上方，3D 場景也讀同一組變數。

| 做法 | 用法 |
| --- | --- |
| 網址 | `?theme=green` / `?theme=blue` / `?theme=red` |
| Console | `__setTheme('green')`（會記在 localStorage，也是離開首頁動線示範後要回去的那一個） |
| 寫死 | `js/main.js` 的 `setTheme(... ?? 'blue')` |

要調成別的顏色，只改 `:root` 那一區的 `--brand` / `--brand-hi` / `--bg-*` / `--m-*` 即可，其他都是引用。
（`--m-shade` 是通關「整棟變白」時底部的陰影色，只有那個畫面會用到。）
`--amber`（警語）、`--red`（起火點）、`--exit`（安全出口綠）屬語意色，不隨主題變動。

紅色那一組平常不會用到，是首頁「展示／切換逃生動線」跑動線的那幾秒在用的（抵達出口再換成綠色）。

## 面板樣式

階段卡、四格應對、底部警語都用 `.chamfer`（`css/style.css` 最上面）：**內部不填色，只有一圈漸層細框**，四角倒角。

| 變數 | 作用 |
| --- | --- |
| `--ch` | 倒角大小（階段卡 `.7rem`、四格與警語 `.5rem`，設 `0` 變回直角） |
| `--bw` | 框線粗細（預設 `.5px`，階段卡亮起時 `.75px`） |
| `--stroke` | 框線的漸層，預設由 `--brand-hi` 往 `--brand` 淡出再回升 |
| `--glass` | 內部底色，預設 `none`；只有階段卡填了一層很淡的高光漸層 |

作法：`--ring` 用 `clip-path: polygon(evenodd, 外框…, 內孔…)` 一次畫出中空的八邊形環，
`--shape` 則是同樣尺寸的實心八邊形。兩個偽元素分工：

- `::before` = 玻璃層，套 `--shape` + `--glass`，階段卡再加 `backdrop-filter:blur(7px)`
- `::after` = 框線層，套 `--ring` + `--stroke`

`--ci` 是內孔倒角的起點，往內縮了 `0.5858 × --bw`，斜邊才會和直邊一樣粗。

`--ring` 的點列裡，外圈最後補一次起點、內圈最後也補一次起點 —— **兩圈都要各自閉合**。
少了這兩個補點，外圈的左緣會被當成連往內圈的連接段跳過，框線就會缺左邊那一條。
中間那段「外圈起點 → 內圈起點」和收尾的「內圈起點 → 外圈起點」完全重疊，會互相抵銷，不影響填色。

框線細到 `.5px` 之後會被抗鋸齒吃掉約一半濃度，所以 `--stroke` 的透明度是加倍後的值；
最暗的那一段也留了下限，否則右下角會淡到看不見、看起來一樣像缺一條邊。

兩個要注意的地方：

- **底色和框線都畫在偽元素上，不能畫在元素本身** —— `clip-path` 會連同子元素一起裁切，畫在元素上會把內容裁掉。
- 內容要靠 `.chamfer > *{z-index:1}` 浮在兩層之上，所以**直接子元素不能是純文字節點**（要包成元素）。

### 階段卡亮起

三段各有自己的 `--hot`，色值集中在 `:root` 的 `--stage-0/1/2`，**倒數圓盤和階段卡共用同一組**：

| 段 | 剩餘秒數 | 顏色 |
| --- | --- | --- |
| `0-10` 秒 | 30–21 | 藍 `--stage-0`（= `--brand-hi`，跟著主色走） |
| `10-20` 秒 | 20–11 | 黃 `--stage-1` `#ffb42e` |
| `20-30` 秒 | 10–0 | 紅 `--stage-2` `#ff4a3d` |

`countdown.js` 會把時段寫成 `.timer` 上的 `data-stage`，圓盤的**大數字**、刻度、指標點、「秒」、
「黃金逃生時間」、「把握 30 秒」的數字、彗星光帶全部讀同一個 `--hot`，所以三個顏色只要改 `:root` 那三行。

剩下 5 秒以內時 `countdown.js` 會在 `.timer` 加上 `.is-urgent`，大數字用 `urgentBlink` 閃爍
（一秒一次，透明度 1 ↔ 0.22，光暈同步收放）。門檻改 `createCountdown({ urgentAt: 5 })`。

輪到時整張卡都換成該段的 `--hot`：

| 部位 | 變化 |
| --- | --- |
| 框線 | `--stroke` 換成 `--hot`、`--bw` `.5px`→`.75px`，`::after` 加 `drop-shadow` 讓只有框在發光 |
| 玻璃層 | `--glass` 混入一點 `--hot` |
| 圓形 Icon | 邊框、圖示、內外光暈都換成 `--hot` |
| 標題（0-10 秒） | 直接變 `--hot`，另加一圈 `text-shadow` |
| 說明文字 | `color-mix(--hot 42%, --ink)`——帶一點色調並提亮，保留可讀性 |

排版不動（只有整張卡左移 `.35rem` 當位置提示）。

## 倒數圓盤的彗星光帶

內圈（SVG viewBox 裡 `r=118` 那一圈）上有一道**逆時針、兩秒轉一圈**的光帶，`css/style.css` 的 `.comet`，顏色跟著 `--hot` 走。

作法是 `conic-gradient` 沿圓周淡出當尾巴，再用 `mask: radial-gradient(closest-side, …)` 把中間挖空只留最外緣一圈，
最後 `animation: cometSpin 1s linear infinite`。外層 `.comet` 只負責 `drop-shadow`——
光暈要打在外層，否則會套在「還沒遮罩」的整個圓盤上。

| 想改 | 改哪裡 |
| --- | --- |
| 速度 | `.comet i` 的 `animation` 時間（目前 `2s`） |
| 方向 | `@keyframes cometSpin` 的角度正負（`-360deg` = 逆時針）。**改方向時尾巴的漸層也要跟著鏡射**，否則尾巴會跑到頭前面 |
| 粗細 | `.comet` 的 `--r`（目前 `.34rem`） |
| 尾巴長度／濃度 | `conic-gradient` 的色標，角度越大離頭越遠 |
| 半徑 | `.comet` 的 `width`（`59%` = viewBox 的 `r=118`） |

已加 `prefers-reduced-motion` 的關閉規則。

## 放 3D 模型

三種方式，任選：

1. **拖曳**：把 `.glb` / `.gltf` 直接拖到左側模型框。
2. **網址參數**：`index.html?model=./models/xxx.glb`
3. **寫死**：在 `js/main.js` 最下方加 `load('./models/xxx.glb')`。

模型載入後會自動置中、依尺寸調整相機距離；沒有模型時顯示內建的示意平面圖（起火點 + 逃生動線 + 安全出口）。

支援 Draco 壓縮（decoder 走 CDN）。

## 檔案

```
index.html          版面（可編輯物件標了 data-obj / data-label）
css/style.css       主題變數 + 全部樣式，1920×1080 為基準等比縮放
css/editor.css      編輯模式的操作框、控制點、工具列
js/main.js          頁面路由、鍵盤、主題、模型載入入口
js/viewer.js        Three.js 場景，可 mount 到任意容器
js/countdown.js     圓形 30 秒倒數 + 階段卡連動
js/editor.js        版面編輯器（凍結成絕對定位 → 拖曳 / 縮放 / 存檔）
js/guides.js        跨頁共用的參考線
server.mjs          靜態伺服器，另外處理 PUT/DELETE /layout*.json
layout.json         第一頁的版面（自動產生，沒調過就不會有）
layout-home.json    首頁的版面
layout-guides.json  所有頁共用的參考線
```

Console 有 `__viewer` / `__countdown` / `__goto` / `__setTheme` / `__editor` 可直接操作。
